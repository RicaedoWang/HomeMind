## 逐段讲稿

### 【01 封面】0:00

各位好，我是 **[你的名字]**。

我做的是一个智能家居的 AI 管家，叫 **HomeMind**。一句话定位：**让智能家居真正"听得懂人话"**。

它的三个能力——**听得懂、记得住、管得住**——就是这次汇报的骨架。

### 【02 问题】0:15

先说为什么做。

现在的"智能"家居，其实**只是声控**。三个具体的麻烦：

第一，它**记不住你的习惯**——你说了十遍"空调 26 度"，它每天还问你要开几度。

第二，它**听不懂话外之意**——你说"提醒我九点关灯"，它**当场就把灯关了**。

第三，它**没有边界感**——一个账号能控制所有人家的设备。

所以判断是：问题**不在设备不够多**，在于缺了「理解」和「约束」两层。

### 【03 定位】0:50

所以它要会三件事：**听得懂**、**记得住**、**管得住**。

这三件，正好对着刚才三个痛点。而第三条——管得住——才是智能家居**能不能落地**的分水岭。

### 【04 一次交互】1:10

先看一次完整交互。你说「打开卧室灯」，它在背后做了四件事：

**听懂**——"卧室"就是"主卧"；**查记忆**——你习惯暗一点，自动调 40%；**确认安全**——普通开灯直接做，只有高危才问；**记住**——这次调光记下来，下次不用再说。

你感知到的是**"它懂我"**，不是"它跑了几个节点"。

### 【05 听得懂】1:30

第一件事，听得懂。核心一条：**有歧义就反问，绝不替你猜**。

你说"打开灯"，家里有两盏，它反问"客厅还是卧室？"——宁可显得笨，也不替你按下开关。

### 【06 记得住】1:45

第二件事，记得住。核心一条：**记忆的价值不是"存了"，是"能改变行为"**。

你上周说"空调 26 度"，这周说"开空调"，它**直接开到 26 度**。记住一百条，不如关键时用上一条。

### 【07 管得住】2:00

第三件事，管得住——这是我最想讲的一页。

**护栏是独立的一道闸**，不是散落在各处的判断。说"开门锁"，它必须先确认；小明在他自己家，看不到你家的任何设备，越权访问直接拦下、设备状态一点不动。

一句话：智能家居能不能落地，取决于"管得住"，**不是"更聪明"**。

### 【08 查得到】2:25

【时间紧这页一句带过】它还查得到——你导入自己家的说明书，问"空调过滤网多久洗"，它语义召回答案，哪怕字面不重合。

### 【09 证明有用】2:35

那怎么证明它真有用？四层验证：**296** 条单测、**54** 条评测、**43** 项端到端、**32** 项前端冒烟。

这四层**不是重复**，是各自堵不同的洞——单测旁路掉认证、测不到 JWT，只能靠端到端兜住。

### 【10 复盘】2:55

最后讲三个坑，每个都改了我几百行。

第一，**模型不知道今天是几号**——prompt 里的示例日期被当成"现在"，任务一建出来就逾期 5 天。

第二，**报了成功、其实没动**——界面说已开灯，灯没变；顺藤还揪出更狠的：门锁联动会**反向把门锁上**，零报错。

第三，**我的测试把自己的数据删了**——跑一次评测，设备全没了。

这三个都不是"功能没做"，是**"做了但错了、测试没抓到"**。所以我立了条规矩：修完 bug，必须补一条能复现它的用例，还要把修复改回去、确认用例真的会红。

### 【11 边界】3:25

我还没做好的：语音入口、真实设备接入、主动服务。

下一步两件事：**评测红线挂到 CI**，让"能拦住回归"变成仓库里可查的事实；**接真实 ESP32 设备**，让"说一句话灯就亮"从模拟变真事。

### 【12 致谢】3:40

我的汇报到这里。**这个项目最大的收获不是这些功能，是学会了怎么证明它们真的能用。** 谢谢。

## 常见提问的答法（30 秒版本）

**Q：为什么不用现成的 Agent 框架（LangChain Agent / CrewAI）？**
> 我要的是"每个子 Agent 只能碰白名单里的工具"，框架的多 Agent 是多个模型聊天，护栏会散成 N 处。我只要一个裁决点。框架我只取了 LangChain Core 的协议层。

**Q：多 Agent 是不是过度设计？**
> 三个子 Agent 的价值是**工具白名单**——日程管家拿不到门锁。这不是"提高效率"，是第二道安全防线。而且它们共用同一份执行原语，没引入第二套治理。

**Q：Redis / Milvus 到底跑没跑？**
> Redis 真跑了，还做了双向验证——停了容器会自动降级内存、界面照常。语义召回接的是本地 embedding（bge-small-zh），不是 Milvus——4,500 条向量 numpy 暴力算 0.13ms，上向量库是给自己找运维。

**Q：这东西能真接到家里设备吗？**
> 工具层是 MCP 风格 Schema，替换 handler 就能接厂商 SDK。我写了《真实硬件接入方案》（ESP32 + ESPHome + Home Assistant），下一步就是真接一块板子。

**Q：最大的难点是什么？**
> 不是让模型听懂，是**让它别乱动**。我踩的三个坑里有两个属于"静默错误"——不报错、日志干净，只有用户会发现不对劲。

**Q：如果重做一遍，会先做什么？**
> 先把隔离和测试骨架搭好。我这次是做到一半才补端到端验收，中间漏了好几处数据泄漏——包括自己的真实设备库被评测清空过一次。
