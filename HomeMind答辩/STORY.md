# STORY — HomeMind 项目汇报 PPT（产品经理视角）

## ① 汇报定位

这不是学员答辩（"我学了什么、用了什么技术栈"），是**产品经理的项目汇报**：
回答四个问题——**解决什么问题、怎么解决、怎么证明有用、下一步怎么走**。

叙事主线：问题 → 定位 → 能力 → 验证 → 复盘 → 边界。

核心原则（贯穿 12 页）：
- 讲**用户痛点**和**产品决策**，不堆技术名词。
- 每个能力页 = 一个用户场景 + 一个"为什么这么设计"的关键决策。
- 技术是答案的一部分，不是答案本身。技术细节收敛进"关键决策"里，一句话讲清"为什么"。
- 诚实：复盘讲坑、边界讲缺，不讲"未来会更好"的空话。

产品定位一句话：**让智能家居真正"听得懂人话、记得住习惯、管得住风险"。**

## ③ 每页内容细则

### 01 封面
- 主标题：HomeMind
- 副标题一句话定位：让智能家居真正"听得懂人话、记得住习惯、管得住风险"
- 不写"基于多智能体协作的解决方案"这类技术话——那是学员答辩的封面，不是产品汇报。
- 视觉：沿用深色氛围图（夜晚客厅 + 悬浮光点）。

### 02 问题（最该先讲清楚的一页）
三个痛点，每个都落到"用户会看到什么后果"：
1. **听不懂话外之意**：说"提醒我九点关灯"，它当场就把灯关了——它分不清"提醒"和"执行"。
2. **记不住你的习惯**：你说了十遍"空调 26 度"，它每天还问你要开几度。
3. **没有边界感**：一个账号能控制别人家；设备说动就动，没有"该不该做"这道闸。

判断句：问题不在设备不够多，在于缺了**理解**和**约束**这两层。

### 03 定位（三能力对三痛点）
- 听得懂 → 解决"话外之意"
- 记得住 → 解决"重复说"
- 管得住 → 解决"乱动"
一句话：这三个能力，是"智能"和"声控"的分水岭。

### 04 一次交互（用户视角，不是技术图）
用户说"打开卧室灯"，产品在背后做四件事（用户能感知的）：
1. 听懂（"卧室"就是"主卧"，"打开"是动作）
2. 查记忆（你习惯卧室灯暗一点 → 自动调到 40%）
3. 确认安全（普通开灯直接做，高危才问）
4. 记住（这次调光记下来，下次直接按这个来）

判断：用户感知到的是"它懂我"，而不是"它跑了六个节点"。

### 05 能力一：听得懂
- 场景："打开灯"——家里有两盏，它反问"客厅还是卧室？"，而不是闷头开客厅灯。
- 关键决策：**有歧义就反问，绝不替你猜**。宁可显得笨，也不替用户按下开关。
- 技术收敛：规则 + 模型双通道（快且可控），解析前注入"现在几点"（模型没有时钟）。

### 06 能力二：记得住
- 场景：你上次说"空调 26 度"，这次说"开空调"，它直接开到 26 度。
- 关键决策：**记忆的价值不是"存了"，是"能改变行为"**。三层记忆（短期会话 / 长期习惯 / 语义召回），召回结果能反向改工具参数。
- 一句话：记住 100 条，不如关键时用上 1 条。

### 07 能力三：管得住（最独特的产品价值）
- 场景：说"开门锁"，它必须先确认；小明（青岛家）看不到你深圳家的任何设备。
- 关键决策：**护栏是独立的一道闸，不是散落在各处的 if**。高危强制二次确认；跨家庭访问直接 403；每个子 Agent 只能碰自己白名单里的工具。
- 判断：智能家居能不能落地，取决于"管得住"，不是"更聪明"。

### 08 能力四：查得到
- 场景：问"空调滤网多久洗"，它从你导入的说明书里召回答案——哪怕你问的是"过滤网"，原文写的是"滤网"。
- 关键决策：**知识库从"内置 5 条"变成"用户可导入的说明书"**，检索用语义召回（字面零重合也能中）。

### 09 怎么证明有用
四层验证，各自抓不同的东西：
- 296 单测：快、确定性
- 54 评测：红线一票否决
- 43 端到端：真起服务 + 真 JWT
- 32 前端冒烟：点了必须有请求
判断：这四层不是重复，是各自堵不同的洞。

### 10 复盘（三个坑）
每个都是"做了但错了，测试没抓到"：
1. 模型没有系统时钟 → prompt 写死的日期被当成"现在"，今日任务建到 6 天前。
2. "成功"配"失败" → 工具说没成功，系统报成功，界面说已开灯、灯没动。
3. 评测把用户真实数据清空了 → 隔离没做在动作之前。
判断：这三个坑，比任何功能清单都能证明"真做过"。

### 11 边界与 roadmap
诚实说还缺什么：
- 还没做：语音入口、真实设备接入、主动服务（"它"指代消解）
- 已经收掉的降级：Redis 真跑、语义召回接本地 embedding、知识库可导入
- 下一步优先级：① 评测红线挂 CI ② 接真实 ESP32 设备

## ④ 视觉基调（沿用深色科技风）

- 背景 `#0B1120`，强调色 `#38BDF8`（天蓝），语义警示色 `#FB7185`（只在讲风险/坑的页出现）。
- 架构/流程/分派图全部手绘 Box/SVG，不用远程渲染（答辩现场网络抖动会整页空白）。
- 每页字数克制在 100–160 字（产品汇报是"讲"的辅助，不是文档）。

## ⑤ 与旧版的本质区别

| 旧版（学员答辩） | 新版（产品汇报） |
|---|---|
| "我用了 LangGraph、FastAPI、Redis…" | "它听得懂、记得住、管得住" |
| 六层架构图（技术栈） | 一次交互（用户视角） |
| 功能模块：意图识别/记忆/护栏 | 能力：听得懂/记得住/管得住/查得到 |
| "三个坑"当补充 | "三个坑"当复盘主线 |
| "下一步接 Redis" | "下一步接真实设备" |

同一个项目，两种讲法。这次讲的是"产品值多少钱"，不是"我学了多少"。
