HomeMind 项目 · 对照模板第 2–6 页的问答
========================================

说明：以下全部基于 HomeMind 项目的真实实现与实测数据填写。
凡涉及行业数据的，已标注来源与统计口径；项目自身的数据（测试数、耗时）
均为实测值。**没有编造任何百分比**——凡是"模板要 XX%，但项目没这个数"的地方，
都明确写了"没有这个指标"，并给了诚实的替代说法。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【第 2 页 · 为什么需要这个项目】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 行业背景（数据来源已标注，答辩别咬死单个数字）

  1. 市场规模：中国智能家居系统市场 2025 年约 6870 亿元、同比 +21.3%
     （IDC 口径，见易有料引 IDC）。注意：不同机构口径差异极大——
     另有 4800 亿（IIM「智慧家居」口径）、1.2 万亿（万连科技「含全屋/服务」口径）。
     答辩建议只说「数千亿级、双位数增长」，不要报一个精确到个位的数。

  2. 语音交互已是刚需：语音交互激活率 89%，用户每天平均发起 6.3 次语音指令
     （IIM《全球 AI 智慧家居行业分析报告 2026》）。

  3. 设备越来越多、越来越难管：每户平均连接设备数从 2021 年的 2.3 台
     涨到 2025 年的 6.8 台（IIM）。设备一多，"记不住、分不清、管不住"就冒出来。

  4. 仍在早期、增长空间大：全屋智能渗透率 2025 年仅约 12%（IIM），
     一线城市新交付精装住宅智能配套率 68%——早期市场，可讲增量。

■ 核心问题（三个，全部来自项目真实踩坑）

  问题一（听不懂话外之意）：说"提醒我九点关灯"，它当场就把灯关了——
  它分不清"提醒"和"执行"。

  问题二（记不住习惯）：说了十遍"空调 26 度"，它每天还问你要开几度。

  问题三（没有边界感）：一个账号能控制所有人家的设备，设备说动就动。

■ 解决思路

  不是把设备做得"更聪明"，而是补上两层——「理解」（听懂并记住）
  和「约束」（兜住别乱动）。做法是一个智能家居 AI 管家（Agent 中枢）。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【第 3 页 · 我们的目标是什么】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 项目目标

  业务价值（对用户）：听得懂、记得住、管得住——三件事各解决第 2 页一个痛点。

  技术价值（对工程）：
  - 三层记忆（短期 / 长期 / 语义），召回结果能反向改写工具参数
  - 安全护栏是独立节点 + 家庭级多租户隔离（越权 403 零副作用）
  - 四层验证体系（单测 / 评测 / 端到端 / 前端冒烟）

■ 关键指标（诚实标注：哪些是实测、哪些是行业基准）

  · 响应时间（实测）：本地 embedding 单次推理 5.6ms；
    意图解析规则模式亚毫秒级（确定性）。
    （行业对照：智能音箱端侧语音识别延迟 0.08s，那是 ASR 口径，不是本项目。）

  · 效率提升（定性，非百分比）：一句话代替手动翻 App；
    记忆让"开空调"直接按你记下的 26 度执行，不用每天重说。

  · 准确率（⚠ 项目没有"意图识别准确率 %"这个指标，不要编）：
    用 54 条端到端评测全部通过 + 296 条单测来验证正确性。
    行业"语音控制响应准确率 97.3%"是语音识别（ASR）口径，
    与"意图理解准确率"是两码事，答辩时别混用。

  · 用户体验（定性）：有歧义就反问、高危动作二次确认、越权直接拦下。

【第 4 页 · 系统架构设计】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 技术栈（均为实测版本，不是抄的）

  编排      LangGraph 1.2.15 + LangChain Core 1.6.10（只取协议层，不用 Agent 黑盒）
  模型      DeepSeek（OpenAI 兼容协议）+ 规则引擎兜底（双模，任一可独立跑通）
  服务      FastAPI 0.143 + Uvicorn 0.54 + Pydantic 2.14
  存储      SQLite（已开 WAL，单条写入 0.02ms）+ Redis 7.4（短期会话，Docker 真跑）
  语义      本地 embedding bge-small-zh（512 维，fastembed/ONNX）；刻意不接 Milvus
  鉴权      JWT（HS256）+ PBKDF2-SHA256（20 万轮）+ 限流
  前端      零构建原生 Web（无 React/Vite），移动端优先

■ 设计亮点（三个）

  1. 模块化：工具执行的治理逻辑（超时/重试/熔断/幂等）只有一处实现，
     主链路与子 Agent 共用，禁止各写一套。

  2. 多 Agent 协作：三个子 Agent 各有工具白名单，Supervisor 分派 +
     执行前冲突检测 + 失败互相隔离（不是多个模型聊天，是职责隔离）。

  3. 人机协同：有歧义反问、高危二次确认——把"不误操作"从提示词里的
     请求，变成代码里的硬约束。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【第 5 页 · 智能体分工与协作】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

模板列的 4 个 Agent，在 HomeMind 里的对应如下：

  意图识别 Agent   →  parse_intent（规则 + LLM 双模），识别 7 种意图
                       device_control / schedule / schedule_query / knowledge /
                       memory_query / memory_write / chat

  知识检索 Agent   →  knowledge_agent：设备说明书问答。用户可导入说明书，
                       本地 embedding 语义召回（字面零重合也能中）。

  工具调用 Agent   →  device_agent（设备控制/查询/门锁）
                     + schedule_agent（建提醒/查日程）
                     + ToolRegistry（超时/重试/熔断/幂等统一治理）

  结果生成 Agent   →  respond_node：整合工具结果生成应答，并回执记忆写入。

■ 协作流程

  用户一句话 → parse_intent 拆成意图 → Supervisor 按「意图类型 + 工具白名单」
  分派给对应子 Agent → 执行前做冲突检测（同一设备被要求"开"又"关"先问）
  → 子 Agent 并发执行、失败隔离 → respond_node 汇总应答。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【第 6 页 · 核心功能模块：意图识别】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 功能描述

  规则引擎 + 大模型双通道：规则快且可控，大模型兜复杂句式。
  关键纪律：规则词表与 LLM prompt 必须两边同步，否则"规则好用、模型翻车"。

■ 测试用例（全部是评测里真实跑过的）

  ① "打开客厅灯"        → device_control ✅（直接执行）
  ② "提醒我九点关灯"    → schedule ✅（不是 device_control，否则当场关灯）
  ③ "看看今天的提醒"    → schedule_query ✅（只读查询，绝不创建数据）
  ④ "空调滤网怎么洗"    → knowledge ✅（说明书问答）
  ⑤ "打开灯"（家有两盏）→ device_control + 反问澄清 ✅（不闷头开客厅灯）
  ⑥ "今天天气怎么样"    → chat ✅（闲聊兜底）

■ 准确率（⚠ 诚实说明）

  HomeMind **没有**一个独立的"意图识别准确率 95%"这样的百分比指标。
  它靠的是 54 条端到端评测全部通过 + 296 条单测来保证正确性。
  答辩时若被问"准确率多少"，建议答：
    「我没有单独标一个意图准确率，因为单点百分比会掩盖边界情况；
     我用 54 条端到端评测（含安全红线一票否决）来验证，全部通过。」
  这比编一个"95%"可信，也经得起追问。
